- (note) FINDING 1, load-bearing and NOT in the brief: a per-option termination mechanism ALREADY EXISTS and is live, with THRESHOLD semantics, not immediate. AnswerSchemaOption.ending_option (a nullable bool) is counted at answer time into UserSurvey.count_of_ending_options (user_surveys/schemas/mutations/answer_question.py:109-113), and the survey auto-submits only once that count reaches Survey.answers_count_to_end with allow_end_based_on_answer_repeat set (user_surveys/schemas/queries/should_terminate.py:35-41, reason TERMINATION_ENDING_OPTION). Seed survey 7 uses it as three-strikes scoring, not routing. So the ruled 'an option may terminate' is a DIFFERENT intent sharing a verb: routing vs a scored cutoff. The spine must keep them distinct and rule their precedence.
- (note) FINDING 2: should_terminate is a POLLED query the client calls, so today termination is discovered by asking, not decided at answer time. A routing terminate has to be decided when the answer is written, which is a different evaluation site.
- (note) FINDING 3, scopes the migration more tightly than the brief assumed: the LEARNER side is ALREADY fully nullable — UserQuestion.section, UserAnswerSchema.section, UserAnswerOption.section and .question all carry null=True. The AUTHOR side is NOT: AnswerSchema.section and AnswerSchemaOption.survey/section/question are all NOT NULL. So the snapshot can already represent a sectionless question and only the authoring tables cannot. Making sections optional is an author-side nullability migration; the snapshot needs no schema change.
- (decision) RULED: the flow edge lives as two columns ON AnswerSchemaOption — a nullable FK to the target Question plus an action value (fall through / go to / terminate) — not as a separate FlowEdge table. Decisive reason: enrolment already deep-copies this table, so the per-learner snapshot comes free and needs no new copy or remap code. Mirrors how Section.submit_action already stores its pair, and needs no join to evaluate.
- (decision) RULED: the routing terminate is stored SEPARATELY from the existing ending_option, which is left exactly as it is. Where one option carries both, the routing terminate WINS and ends the survey immediately: reaching an authored hard stop cannot be undone by a threshold that has not been met. Prevents a live scored-cutoff feature being overloaded with a second intent, and makes a precedence explicit that would otherwise be emergent.
- (decision) RULED: forward-only is validated when the edge is saved AND re-validated when a question is reordered; a reorder that would invert an existing edge is refused with a named field error. Closes the hole that save-time-only checking leaves, since position is mutable and evaluation relies on the forward-only guarantee to skip cycle detection.
- (decision) RULED: the legacy Section.submit_action / submit_action_target pair is REFUSED AT THE API now and dropped later, not dropped in this work. Keeps consistency with the sibling canvas spec's CAP-9, which already owns that refusal, and avoids adding a column drop to a release that already carries two live-data migrations.
- (decision) RULED: the SERVER is the authority on the next question. answerQuestion returns the next question or that the survey ended, and the solver follows it; the solver never computes the path itself. One implementation of the rule, so itq_forms and lyr-surveys cannot diverge on what 'reached' means — which the score basis depends on. It also moves a routing terminate to the write path, rather than leaving it to be discovered by a later should_terminate poll.
- (decision) RULED: fallthrough running off the end COMPLETES the survey, exactly as reaching the last section does today. No explicit-terminate obligation on authors; matches the behaviour every existing survey already has.
- (decision) RULED: each live-data migration ships behind a management command with --dry-run reporting counts and affected survey ids, reviewed before the migration ships, and the data migrations go in their OWN release separate from the schema and feature code, each with a documented reversal. Forced by the constraint that every push of itq_forms main is a real production release with no quiet revert.
